# Consent stored authority contract v1 — 2026-10-28

Status: Consent candidate implementation authorized. **Integration acceptance and deployment blocked on the Ads consumer contract below.** The request ended mid-sentence; independent work follows the already reviewed REPAIR-PROPOSAL.md scope. No application writes are part of this assignment.

## Stored stamp

`response._se_consent_server` is owned by Consent. `contract_version: 1`, `state: verified`, a genuine receipt_id and receipt_row_id mean the request supplied a signed, unexpired acknowledgement matching exactly one immutable stored event, its policy/banner and its stored category/Google values. Verified means recorded choice, including rejection; it never itself means advertising permission. All other states are negative and contain an empty receipt_id, row ID 0 and denied optional categories/Google flags. No fake ID, fake denial row or historical rewrite may be used to defeat fallback. Both positive and negative stamps carry a form_id-bound HMAC signature. Consumers must call `SiteEngine_Consent_Authority::verify_stamp($stamp, $canonical_form_id)` and match `receipt_digest` to `SiteEngine_Consent_Authority::receipt_digest($exact_row)`. Presence of a v1-looking array alone is not authentication. Signature verification does not bypass any eligibility gate. Site auth-salt rotation invalidates signatures/ACKs; no unsigned fallback is allowed.

Untrusted nested stamps and every trimmed top-level se_consent_*/se_google_* field are removed, then canonical flat diagnostic fields and the owned nested stamp are regenerated. Unrelated form fields survive. A successful capture also requires the form's current `se_consent_receipt_id` to exactly echo the signed cookie receipt; absent/blank/mismatched echo yields conflicting_claim. This prevents a pending choice or failed cookie write from silently reusing an earlier granting cookie. Contradictory cookie state also fails closed; it is not repaired from the signed record. The response-array filter runs after normal component transforms; a separate submission_form_data filter reapplies the same captured decision before entry details/integrations. Entry details receive canonical flat values (blank receipt omitted by Fluent Forms); the nested stamp is expanded by Fluent Forms' existing detail serializer. No direct vendor-table writes or deletions occur. The response decision is frozen within a submission request; a later audit acknowledgement cannot upgrade that stored form. Sites that do not retain the receipt hidden field through Fluent Forms sanitization will fail closed and require controlled lifecycle acceptance; no broader cookie-only fallback is provided.

Missing, pending, failed, stale, malformed, tampered, unsigned legacy, ambiguous or unavailable authority never acquires a receipt ID from hidden fields. Legacy receipt rows and unsigned browser state remain untouched and cannot become new v1 authority. New explicit interactions create new event IDs. An acknowledged rejection remains a verified negative choice. Cookies are bearer evidence, not authenticated identity; signed acknowledgements prove server storage/integrity, not the truth of a visitor's assertion or legal permission.

## Capture and browser state

New interaction IDs are browser UUIDs; the server derives a namespaced receipt ID using a site secret. It never accepts an old arbitrary receipt ID for append. A database advisory lock serializes retry/replay per event across workers; lock/query failures fail closed. Identical retry returns the existing row; conflicting retry/duplicate rows fail. No unique-index migration or legacy deduplication occurs. Category values must be booleans; Google flags are server-derived. Policy/banner must match configuration; client metadata never selects retention time. Server timestamps and signed row digest/expiry bind the acknowledgement to the persisted event. State is acknowledged only after durable insert/readback; storage failure yields no authority.

Each actual interaction gets a new ID; retry retains its ID. Old acknowledgements cannot restore a newer preference, including cross-tab changes observable in storage/cookies. Local rejection applies immediately. Pending/failed audit never carries an earlier granting ID. The business form itself remains usable; its consent evidence is negative if acknowledgement has not arrived. Legacy, expired and mismatched policy/banner state requires explicit choice; policy value itself is unchanged. No retrospective form upgrade or historical repair.

## Why unchanged Ads 0.6.3 is insufficient

tests/consumer-contract.php executes the actual SHA-256-pinned 0.6.3 resolver with synthetic in-memory storage. It demonstrates that an empty negative stamp can still export through an existing flat/details grant, and that a reused historical ID resolves later choices. Fresh response plus fresh sanitized details block correctly; that does not protect preexisting details, historical reprocessing or all alternate persistence paths. Changing future Consent IDs cannot fix legacy newest-row resolution. Treat the unsafe fixture outcomes as blockers, not acceptance passes.

Required Ads-owner assignment (prepared in ADS-CODEX-ASSIGNMENT.md): if a v1 stamp is present, it must veto all fallback unless structurally valid, signed for the canonical form, and verified. Resolve exact receipt ID AND row ID, require unambiguous matching immutable evidence and signed digest, preserve policy/DNC/deterministic-source/ad_user_data gates and independent ad_personalization. Legacy absent-v1 handling must be explicitly fail-closed for unsigned/ambiguous receipt identity; do not silently bless historical grants. Missing, corrupt or negative v1 evidence must never fall through to a flat/details ID. Consent must not edit Ads to obtain that behavior.

## Acceptance boundary

No WP installation, actual Fluent Forms submission, payment path, web/cache, database-engine lock/durability or external export is accepted by these tests. Controlled installation/lifecycle acceptance requires later explicit authorization and the coordinated consumer fix.
